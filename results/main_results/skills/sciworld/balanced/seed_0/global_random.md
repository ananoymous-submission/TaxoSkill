

## Additional Successful Procedures
- After entering the task room, use `look around` to see visible objects and containers.

- **Category-typical rooms**: When the task names only an object category (plant, animal, thermometer, electrical part) rather than a location, go first to the room that usually contains that category—greenhouse for plants/seeds, outside for animals, kitchen for food/thermometer, workshop for electrical parts—and `look around` there before a broad sweep.
- **Terse `examine` results**: If `examine OBJ` returns only a terse object name, do not wait for more detail. Use real-world domain knowledge for comparisons and classifications (such as life-span ordering, living versus non-living, and metal conductivity) and proceed with the task.

- **Task-specified locations and ordered focuses**: When the task names a target location, teleport directly there and `look around` before searching unrelated rooms. If the needed object/substance is not visible, search that location's containers and nearby category-relevant rooms before doing a broad sweep of all rooms. For ordered focus tasks, focus on each named target as soon as it is present and identified; do not wait for a target that is already present to grow, hatch, or die, and do not stop after only the first focus in the sequence. If a required later stage is not present, search/revisit the initial and adjacent category-typical rooms and their containers/habitats; if the missing stage is an egg or juvenile of the same species, `wait` and re-examine it there before sweeping unrelated rooms. Avoid opening empty drawers/cupboards far from the expected location while an earlier stage is still in its starting room.
- **Temperature measurement**: Locate a thermometer (if not in the task room, check the kitchen). `focus on thermometer`, then `pick up thermometer` before leaving the room when the target substance is elsewhere—`focus on` does not move a tool into inventory. Bring it to the target room so the thermometer and target are in the same room, focus on the target substance, then `use thermometer on <substance>`. Compare the measured value to the task threshold and `move <substance> to <box>` as required; if the destination box is in another room, `pick up <substance>` before teleporting there.
- **Heating device fallback**: If one heat source is broken or missing, switch to another suitable device (for example use the `oven` when the `stove` is broken) before concluding the task cannot proceed.
- **Plant growth observation**: After ensuring a seed is planted in a container with soil and water, repeatedly `wait` and `examine flower pot N` to observe growth stage changes before declaring completion.

## Command Grammar and Object References
- Use native action verbs (`pick up`, `move`, `open`, `close`, `look at`, `examine`, `use ... on ...`, `pour ... into ...`, `mix`, `focus on`, `activate/deactivate`, `connect/disconnect`, `teleport to ...`). Do not use `take`; use `pick up OBJ`. For an object inside a closed container, first `open CONTAINER`, then `look at CONTAINER`, then `pick up OBJ` if needed.
- For `pick up`, `pour`, `mix`, and `move`, refer to the object/container by its observed name; do not append contents lists or descriptive phrases such as `wood cup with red paint`. Use `look at inventory`, `look at OBJ`, or `examine OBJ` to identify contents first.
- When an action returns an ambiguity prompt, respond with only the number of the intended option (for example `2`). Select the number matching the intended object's location/contents; do not choose blindly. For identical containers/cups, disambiguate candidates first with `look at OBJ` / `examine OBJ` and track their observed contents and positions; do not assume the prompt order corresponds to contents. Do not send forms such as `open drawer 0`, `mix tin cup 0`, or parenthesized phrases. If the chosen number errors and the ambiguity prompt is gone, re-issue the underlying action to get a fresh prompt, then choose a different number. A simple location qualifier such as `open drawer in cupboard` may also disambiguate when supported. After `pour` or `move` among identical containers, immediately `look at inventory` or `look at OBJ` to confirm the resulting contents.

## Domain Procedures
- **Liquids and state changes**: Do not `pick up` or `take` a liquid directly. Move an empty container into a liquid source, or use a sink/bathtub with the drain closed and the fixture activated, then pick up the filled container. Heat or freeze the contained liquid in a device, wait, then examine the container to see the resulting solid/liquid/gas.
- **Plants**: Each planted seed should have a container with both soil and water. If soil is missing, dig with a shovel on ground to expose soil, then `pick up soil`; avoid moving soil away from a planted container to fill another.
- **Electric circuits**: Before connecting, examine polarized parts for anode/cathode or terminal names. Build one closed series loop with compatible polarity: connect the battery's **cathode** to the first component's **anode**, each component's **cathode** to the next component's **anode**, and the final component's **cathode** back to the battery's **anode**. A reliable loop is: `battery cathode` -> `wire terminal 1`, `wire terminal 2` -> `switch anode`, `switch cathode` -> `wire terminal 1`, `wire terminal 2` -> `bulb anode`, `bulb cathode` -> `wire terminal 1`, `wire terminal 2` -> `test object terminal 1`, `test object terminal 2` -> `battery anode`. If a terminal is already connected, disconnect it before reconnecting it elsewhere. Activate the switch, then `examine OBJ` to check the bulb. If the bulb is off, verify every connection and the switch/battery state, then test the circuit with a known conductor or swap the bulb/wire/switch before concluding the test object is non-conductive.
- **Color mixing**: Combine the required paints or liquids in one container, then use `mix CONTAINER` rather than a contents-based name. For multi-step production, plan source materials before mixing: if an intermediate must later be modified, locate and preserve extra primary pigment instead of consuming all of it in the first step.

- **Recipe and non-color mixing**: When the task asks to create a substance with a recipe hint, go to the hinted room, `look around` to locate the recipe and raw ingredients, then read the recipe with a short reference (`read recipe` or `read <short title>`) if `read recipe titled ...` is rejected. Gather all required ingredients into one clean, empty container and use `mix CONTAINER`. If `mix CONTAINER` does not produce the desired substance, check whether the container has unrelated contents and, if so, move the required ingredients into an empty container and `mix` again. Finally `focus on <final substance>` rather than the container.

## Focus and Task Completion
- Treat `focus on OBJ` as required at the moment the target object is present. For multi-step or ordered tasks, focus on each item as soon as it is observed, before it can hatch, grow, melt, move, or otherwise disappear.

- If `focus on OBJ` returns `No known action matches that input`, the target is not present/visible in the current room. Do not retry the same focus command. Teleport to the room where the target is likely or named to be, `look around`, and focus only after the object is observed.

- `focus on OBJ` does not move the object into inventory. If a later step requires moving the focused object into a box in another room, first ensure the object is in inventory or already in the destination room; otherwise go back, `pick up OBJ`, then return/teleport to the destination and issue `move OBJ to BOX`.
- After creating or changing a substance, focus on the final substance exactly named in the task, not only the container that holds it.
- For conditional tasks with boxes or thresholds, make the final focus/placement as soon as the evidence is sufficient; do not continue refining after the needed state change or comparison is already clear.

## Animals and Living Things
- When the task asks to find, focus on, or move a living thing, identify and focus on the living thing itself by its observed name (for example `lemon tree`, `baby brown bear`, `adult bee`), not its pot, hive, egg, or other container. If it is inside a closed container or hive, open it and use `look at`/`examine` to learn the living thing's name first.
- For a moving target, `focus on` it and `pick up` it **before** teleporting away or checking the destination; animals and other self-moving objects can move, escape, hatch, grow, or change names if left behind.
- If `pick up <animal>` or `move <animal> to <box>` fails or returns `No known action matches that input`, do not retry the same command or repeatedly try to move its container/habitat. Re-check the exact object name with `look around` or `examine OBJ`, then use `pick up OBJ` for loose animals/objects. If a mobile animal cannot be picked up directly, first contain it by using `move <animal> to <portable container>` while in the same room. Keep it contained while traveling to the destination, then move it or its container as required and verify immediately with `look at <box>` and `look at inventory`. If the box/container is empty afterward, the animal escaped; do not retry the same vanished animal. Go back to a location with other live animals and choose a different individual, or use another visible animal/juvenile/egg if the task requires only one instance of a category.
- For `longest life span` tasks, do not spend actions searching every room for a reference book and do not wait for eggs or juveniles to grow before answering. Rank the visible animal species by real-world lifespan and focus on the longest-lived species as soon as it is identified.

## Stop After Task Completion
- As soon as the required focus has happened and the required object/substance/animal has been moved or placed into the required container/location, stop taking further verification actions such as `look at`, `look around`, repeated `focus on`, or `wait`. Continuing after completion can trigger environment truncation and does not improve the score.
